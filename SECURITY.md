# Security policy

## Reporting a vulnerability

Report privately through this repository's **Security** tab, under **Report a vulnerability**. That
opens a draft advisory only the maintainers can see, and it keeps the report attached to the repo it
concerns.

If private reporting has not been enabled on this repository, email the security contact instead:
`SECURITY_CONTACT` — *replace this placeholder with a real address when creating a repo from the
template.*

Do not open a public issue or pull request for a vulnerability, and do not post one in a public
discussion. A public report tells everyone about the hole at the same moment it tells us.

Include whatever you have: what an attacker can do, the steps to reproduce it, and the affected
version or commit. A partial report is worth sending; wait for certainty and the window stays open
longer than it needs to.

## What happens next

You will get an acknowledgement that a person has read the report, usually within a few working
days. A fix timeline comes after triage rather than with the acknowledgement, because it depends on
what the report turns out to be. Neither is a contractual commitment — this is a small team, and
saying otherwise here would not make it true.

We will tell you when the fix ships, and credit you in the advisory unless you would rather we did
not.
